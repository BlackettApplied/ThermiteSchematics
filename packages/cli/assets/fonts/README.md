# Printable fonts

Unmodified Noto Sans Regular, Bold and Math TrueType fonts live once in
`packages/render/assets/fonts/` for exact metrics and CLI SVG/HTML/PDF export.
CLI resolves them relative to the existing `@thermite/render` package export;
the current runtime closure already includes its assets. Mono remains in this
CLI directory. Each package retains OFL.txt, the upstream SIL Open Font License
1.1. These fonts do not embed electrical component libraries.

Noto Sans Math Regular supplies missing mathematical and arrow glyphs, including
U+2212 MINUS SIGN and U+2192 RIGHTWARDS ARROW. PDF export uses font-only spans for
those glyph runs; ordinary text keeps Noto Sans Regular/Bold. Source strings,
SVG/HTML use the same bundled mathematical fallback; anchors and coordinates are unchanged. Characters absent
from both bundled families are still rejected. All fonts are loaded offline.

The renderer's committed `text-metrics-data.ts` is generated by
`bun scripts/update-text-metrics.mjs --write` and checked by
`bun run check:text-metrics` (also part of `bun run check`). It stores a deflated,
base64-encoded stream of delta code points, envelope/vertical bounds in 1/10000
em, and drawable embedded-face masks, together with source SHA-256 hashes. Data
is decompressed once; fitting and coverage never parse fonts. The runtime ships
only compact generated JavaScript and its declaration, without its source/maps.

The per-glyph envelope explicitly covers these generator inputs:

- The four bundled Noto faces listed above, retaining their 10% reserve.
- Liberation Sans Regular/Bold from the lock-pinned `pdfjs-dist` 6.5.438
  `standard_fonts/` directory (see its `LICENSE_LIBERATION`). These PDF.js copies
  are 669-code-point subsets (ASCII, Latin-1/Extended-A and selected Greek,
  Cyrillic, punctuation, mathematical and box-drawing code points listed in
  their cmap, enumerated below), so the bound does not cover the full system
  Liberation Sans.
- DejaVu Sans and Sans Mono, Regular/Bold, from **dev-only**
  `dejavu-fonts-ttf` **2.37.3** (DejaVu 2.37). The exact version and tarball
  integrity are recorded in `bun.lock`; upstream package:
  https://registry.npmjs.org/dejavu-fonts-ttf/-/dejavu-fonts-ttf-2.37.3.tgz
  and https://github.com/senotrusov/dejavu-fonts-ttf/tree/160a1b453852fef89b036c8c466e79b479a4fcd0.
  See that package's `LICENSE`. Neither the package nor these font files ships
  in the runtime. Liberation fonts likewise remain development-only.

Measured browser-face advances and ink bounds are combined by maximum, without
an arbitrary percentage standing in for their glyph metrics. Proprietary
Arial/Helvetica, Courier and Menlo are **not** claimed as per-glyph bounds;
browser fonts or user CSS outside the explicitly measured faces remain a
limitation. The pinned DejaVu envelope covers operators such as `+` and `=`.

Unknown clusters receive 1.5 em width, 1.2 em ascent and 0.4 em descent, once per
cluster. This allows a fullwidth 1 em fallback glyph plus 50% horizontal bearing
reserve and a fixed vertical accent allowance. Unknown attached marks add no
advance or repeated vertical allowance. These are fallback allocations, not a
proof for arbitrary installed fonts. If unknown text cannot fit, R006 names
those glyphs and the report row's designation when available.

Text is NFC-normalized before measuring and emitting report/loop labels, and
before direct PDF conversion. Canonical composition preserves accents that have
precomposed glyphs. Because svg-to-pdfkit cannot paint zero-advance glyphs or
position combining marks, residual real marks explicitly fail PDF export with
code point, Unicode category, sheet, report-row designation and column when
available. Categories come from fixed JavaScript Unicode-property checks; no
character-name database is used.
Default-ignorable characters (including SHY, ZWSP, WJ, bidi controls, BOM,
variation selectors and unsupported ZWJ/ZWNJ sequences) have zero measured
advance/ink and are removed only from PDF's text before font validation; their
visible neighbours must still be supported. SVG/HTML retains the source
characters for browser handling. Unsupported visible glyphs are never dropped.
Wrapping preserves normalized text and whitespace, hanging break spaces
on the preceding line; only overlong tokens split. Edge whitespace remains in
SVG text content using `xml:space="default"` spans, without visible indentation.

The render package supplies the shared Regular, Bold and Math sources for exact printable metrics.
R2's shared model bounds individual glyphs and has no OpenType feature model.
GPOS, GSUB, GDEF and legacy/AAT layout tables are removed consistently before
Fontkit exact metrics, browser subsetting and PDFKit font registration. No
kerning, ligature or contextual/mark OpenType feature is delivered. NFC and
Unicode fallback positioning remain; exact metrics use the same feature-free
face. Full feature-free TTF faces retain original glyph IDs, outlines, advances and
hinting; SVG/HTML delivery additionally removes hinting.

CLI SVG file delivery embeds a deterministic per-document WOFF subset; packet
HTML has one shared font block in its head. Fontkit 2.0.4 supplies glyph selection
and compound closure; pure-JS pako 0.2.9 avoids native/platform compression
variation. Raw render/agent JSON and goldens contain family names only. PDFKit
embeds its own subsets from the same feature-free TTF faces. The full multi-face
block is hash-pinned, and each standalone SVG is limited to 61,440 font bytes.
The shipped-example test and E3 independently check that limit. Original OFL
notices apply. Original source faces remain byte-identical for sourcing and the
R2 conservative-metric generator.

SVG/HTML subsets omit TrueType hint programs (global and glyph instructions),
grid-fitting tables and all OpenType shaping tables. Original selected advances
and outlines remain unchanged. The pinned JavaScript encoder and compressor
produce deterministic bytes without platform font APIs. PDFKit continues to
subset the full feature-free bundled faces itself; this SVG hint removal does
not change that PDF path. Font-budget overflow returns `R007`, exit 1; export
`.html` or `.pdf` for SVG overflow; use `.pdf` for HTML overflow.

Thermite Math is subset only from the document's NFC characters that Regular
lacks; ASCII and other primary-face text are not duplicated into the fallback.
The 61,440-byte limit is a byte budget, not a fixed character count: the boundary
depends on glyph complexity, weights and the fallback repertoire.

With the measured distinct supported Latin/Greek/Cyrillic and reviewer mixed-script
specimens, Regular plus one bold title first refuses at 458–502 characters,
including the one-Math-glyph cases; Regular-only first refuses at 931–949 in
codepoint order. The mixed-script Regular-only specimen still fits through
890 characters (891 including Math). These are specimen boundaries, not a
universal character limit; Math is never populated with primary-face text.
